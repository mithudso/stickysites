# StickySites: Sourced Project Facts

One declarative fact per line, each with a `[src:]` tag.

## 2026-09-27 [gen: repo-bootstrapper/1.0]

- StickySites is a Chrome Extension on Manifest V3 written in vanilla JavaScript with no build step [src: CLAUDE.md]
- manifest.json is the canonical version file (1.11.2) and package.json must match; `npm run lint` fails on drift [src: scripts/check-syntax.mjs]
- There are six note types: Global (yellow), Site (green), Page (blue), To-do list (purple), Outliner (orange), Daily (red) [src: src/content/note-types.js]
- Site notes are keyed by hostname without www, Page notes by origin plus pathname, Daily notes by YYYY-MM-DD [src: src/content/note-types.js]
- The outliner is a global library of named documents keyed ol_<id>; the active doc is the activeOutlineId pref [src: src/content/outline.js]
- Alt+S toggles the cluster and Ctrl/Cmd+F1 through F6 toggle the six note types; there are no bare-key hotkeys [src: src/content/sticky-inject.js]
- The editor auto-saves after a 500 ms debounce and flushPendingSave() commits early on close, switch, popout, or SPA re-key [src: src/content/panel.js]
- The panel snapshots its storage key at open() so a save can never land under another page's key [src: src/content/panel.js]
- Encryption is opt-in AES-256-GCM with a PBKDF2 key derived at 600,000 iterations using SHA-256 and a 16-byte salt [src: src/content/crypto-content.js]
- The derived key is cached as a JWK in chrome.storage.local under stickysites_cached_key and persists until Lock Now; chrome.storage.session is not used [src: src/content/crypto-content.js]
- An encrypted value is an object with string iv and data fields and no body, items, or siteKey field [src: src/content/crypto-content.js]
- The permissions are storage, activeTab, contextMenus, alarms, and nativeMessaging [src: manifest.json]
- Content scripts are ten classic scripts loaded in manifest order, each attaching a namespace on window.StickySites [src: manifest.json]
- The service worker is an ES module that handles context menus, the Alt+S command, the popout window, and the to-do sync [src: src/background/service-worker.js]
- The to-do sync calls chrome.runtime.sendNativeMessage to the host com.mitch.todo_bridge on startup, on install, every 2 minutes via chrome.alarms, and 3 seconds after the todos key changes [src: src/background/service-worker.js]
- The native host owns the three-way merge with TODO.md; the extension re-attaches StickySites-only fields and writes only when the canonical JSON changed [src: src/shared/todo-bridge.js]
- The to-do sync is skipped while the todos value is an encrypted envelope so plaintext never reaches the file [src: src/shared/todo-bridge.js]
- The native host is installed outside the repo by python3 ~/.claude/skills/todo/scripts/todo.py install-native-host [src: docs/external-calls.md]
- The only out-of-browser call is that native-messaging sync; there are no network calls, telemetry, or third-party scripts [src: docs/external-calls.md]
- The test command is npm test, which runs vitest with 4 files and 101 tests in a node environment with chrome mocked [src: docs/TESTING.md]
- Unit tests cover notes-storage (50), todo-bridge (23), outline-ops (21), and crypto (7) [src: docs/TESTING.md]
- CI runs npm run lint, npm test, npm run docs:check-indexes, and a manifest validation step on every push and pull request to main [src: .github/workflows/ci.yml]
- npm run docs:check-indexes validates every path in docs/high_signal_file_index.json and every relative link in llms.txt [src: scripts/check-doc-indexes.mjs]
- npm run verify:live drives Chrome for Testing with puppeteer-core because branded Chrome 137+ ignores --load-extension [src: scripts/verify-live.mjs]
