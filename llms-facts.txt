# StickySites: Sourced Project Facts

One declarative fact per line, each with a `[src:]` tag.

## 2026-09-27 [gen: repo-bootstrapper/1.0]

- StickySites is a Chrome Extension on Manifest V3 written in vanilla JavaScript with no build step [src: CLAUDE.md]
- manifest.json is the canonical version file (1.13.0) and package.json must match; `npm run lint` fails on drift [src: scripts/check-syntax.mjs]
- There are six note types: Global (yellow), Site (green), Page (blue), To-do list (purple), Outliner (orange), Daily (red) [src: src/content/note-types.js]
- Site notes are keyed by hostname without www, Page notes by origin plus pathname, Daily notes by YYYY-MM-DD [src: src/content/note-types.js]
- The outliner is a global library of named documents keyed ol_<id>; the active doc is the activeOutlineId pref [src: src/content/outline.js]
- Alt+S toggles the cluster and Ctrl/Cmd+F1 through F6 toggle the six note types; there are no bare-key hotkeys [src: src/content/sticky-inject.js]
- The editor auto-saves after a 500 ms debounce and flushPendingSave() commits early on close, switch, popout, or SPA re-key [src: src/content/panel.js]
- The panel snapshots its storage key at open() so a save can never land under another page's key [src: src/content/panel.js]
- Encryption is opt-in AES-256-GCM with a PBKDF2 key derived at 600,000 iterations using SHA-256 and a 16-byte salt [src: src/content/crypto-content.js]
- The derived key is cached as a JWK in chrome.storage.local under stickysites_cached_key and persists until Lock Now; chrome.storage.session is not used [src: src/content/crypto-content.js]
- An encrypted value is an object with string iv and data fields and no body, items, or siteKey field [src: src/content/crypto-content.js]
- The permissions are storage, activeTab, contextMenus, alarms, and nativeMessaging [src: manifest.json]
- Content scripts are ten classic scripts loaded in manifest order, each attaching a namespace on window.StickySites [src: manifest.json]
- The service worker is an ES module that handles context menus, the Alt+S command, the popout window, and the to-do sync [src: src/background/service-worker.js]
- The to-do sync calls chrome.runtime.sendNativeMessage to the host com.mitch.todo_bridge on startup, on install, every 2 minutes via chrome.alarms, and 3 seconds after the todos key changes [src: src/background/service-worker.js]
- The native host owns the three-way merge with TODO.md; the extension re-attaches StickySites-only fields and writes only when the canonical JSON changed [src: src/shared/todo-bridge.js]
- The to-do sync is skipped while the todos value is an encrypted envelope so plaintext never reaches the file [src: src/shared/todo-bridge.js]
- The native host is installed outside the repo by python3 ~/.claude/skills/todo/scripts/todo.py install-native-host [src: docs/external-calls.md]
- The only out-of-browser call is that native-messaging sync; there are no network calls, telemetry, or third-party scripts [src: docs/external-calls.md]
- The test command is npm test, which runs vitest with 5 files and 125 tests in a node environment with chrome mocked [src: docs/TESTING.md]
- Unit tests cover notes-storage (50), peer-sync (24), todo-bridge (23), outline-ops (21), and crypto (7) [src: docs/TESTING.md]
- CI runs npm run lint, npm test, npm run docs:check-indexes, and a manifest validation step on every push and pull request to main [src: .github/workflows/ci.yml]
- npm run docs:check-indexes validates every path in docs/high_signal_file_index.json and every relative link in llms.txt [src: scripts/check-doc-indexes.mjs]
- npm run verify:live drives Chrome for Testing with puppeteer-core because branded Chrome 137+ ignores --load-extension [src: scripts/verify-live.mjs]
- src/shared/notes-storage.js is imported only by tests; the extension runtime reads and writes chrome.storage.local directly [src: docs/known-issues.md]

- Production code logs only console.warn('[stickysites] …') on service-worker failure paths and never logs note content or key material [src: docs/logging.md]

- To install, open chrome://extensions, enable Developer mode, choose Load unpacked and select the repo root [src: docs/INSTALLATION.md]
- Local peer sync keeps laptops on the same LAN converged: the service worker pushes a snapshot to a loopback daemon at http://127.0.0.1:47831 every minute and 4 seconds after a note changes, then merges every peer's snapshot [src: src/background/service-worker.js]
- The peer daemon peer/stickysites-peer.py is stdlib Python; it discovers peers with HMAC-signed UDP announcements on port 47833 (multicast 239.255.77.31 plus subnet broadcast on every non-tunnel interface, plus optional unicast to static peers) and relays snapshots over HTTPS on port 47832 with a pinned self-signed certificate and a bearer token derived from the pairing key [src: peer/stickysites-peer.py]
- Peer merge is record-level last-writer-wins on updatedAt with tombstones; ties keep the local copy; prefs and the cached key never sync [src: src/shared/peer-sync.js]
- Peer sync never mixes vaults: same salt merges on decrypted data, different salts report mismatch and write nothing, and a laptop with encryption off adopts a peer's vault config and locks [src: src/shared/peer-sync.js]
- The peer daemon's loopback API accepts only chrome-extension:// origins via CORS, so no host permission was added to the manifest [src: peer/stickysites-peer.py]
- Only outline document deletion writes a tombstone today because no other note type has a delete action in the UI [src: docs/known-issues.md]
- The popup Settings can set the peer pairing key and a comma-separated list of static peer IPs; the daemon hot-applies them through GET/PUT /config on loopback and writes them to ~/.stickysites/peer.json [src: popup.js]
- The popup Test connection button calls the daemon GET /test, which connects to each peer (TCP, TLS fingerprint, GET /hello with the bearer token) and reports the first failing step with a cause hint; a No route to host at the tcp step means a VPN or the macOS Local Network gate is blocking the helper [src: peer/stickysites-peer.py]
- install wraps the daemon in an ad-hoc-signed ~/Applications/StickySites Peer.app so a VPN bypass list or the macOS Local Network permission can name it [src: peer/stickysites-peer.py]
- The peer daemon can also sync through a shared folder: with sync_dir set (popup Sync folder field or the folder CLI) it writes a pairing-key-signed stickysites-peer-<id>.json on every snapshot change and reads every other laptop's file as a peer, so Google Drive or an SMB share can carry the sync without any network path [src: peer/stickysites-peer.py]
